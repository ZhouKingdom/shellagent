# ShellAgent 任务生成流程复现记录


> 项目路径：`/data/dhsun/shellagent`

---

## 一、任务生成的入口脚本和完整流程

### 入口脚本

```bash
NUM_TASKS=<任务数> OUT_DIR=<输出目录> \
    bash rl_data/scripts/generate_tasks/run_generate_tasks.sh
```

### 完整流程（4 阶段管线）

```
Stage 1: 任务模板生成 (task template generation)
  └─ 调用 LLM API → 根据组合式轴采样生成 task.json

Stage 2: 初始状态测试生成 (initial state test generation)
  └─ 调用 LLM API → 生成 test_initial_state.py

Stage 3: 最终状态测试生成 (final state test generation)
  └─ 调用 LLM API → 生成 test_final_state.py（程序化验证器）

Stage 4: 容器构建 + 冒烟测试 (container build + smoke test)
  └─ 生成 container.def → Apptainer 构建容器 → 运行测试验证可执行
```

### 管线由 `rl_data/generate_tasks.py` 驱动

核心配置类 `PipelineConfig`，可配置参数：

| 参数                | 默认值                          | 说明                           |
| ------------------- | ------------------------------- | ------------------------------ |
| `num_tasks`         | 必填                            | 任务数量                       |
| `model`             | `gemini/gemini-3.1-pro-preview` | LLM 模型                       |
| `max_tokens`        | 32768                           | 最大 token 数                  |
| `task_temperature`  | 1.0                             | 任务生成温度                   |
| `test_temperature`  | 0.6                             | 测试生成温度                   |
| `corpus_kind`       | `legacy`                        | 语料类型 (legacy/sft_v2/rl_v2) |
| `def_build_workers` | 4 → 脚本覆写为 16               | 容器构建并发数                 |

## 二、输入与输出

### 输入

任务生成 **不需要任何输入文件**，所有任务内容由 LLM 根据组合式轴采样自动生成。

只需要配置：
1. **LLM API Key** — 调用模型生成任务内容


## 输出：每个任务的目录结构

```
rl_data/output/<OUT_DIR>/
├── task_000000_<8位hash>/
│   ├── task.json              # 任务描述、正确答案、采样轴信息
│   ├── test_initial_state.py  # 初始环境状态验证
│   ├── test_final_state.py    # 最终状态验证（程序化验证器）
│   ├── container.def          # Apptainer 容器定义文件
│   └── setup.sh               # 环境初始化脚本
├── task_000001_<8位hash>/
│   └── ...
├── _intermediates.jsonl       # Stages 1-3 中间结果（断点续跑用）
└── _stage4_done.jsonl         # Stage 4 完成记录
```

### task.json 字段说明

| 字段                 | 类型 | 说明                                                      |
| -------------------- | ---- | --------------------------------------------------------- |
| `name`               | str  | 任务名 (如 `task_000000_xxx`)                             |
| `description`        | str  | 任务描述（发给 agent 的提示）                             |
| `truth`              | str  | 正确答案 / 期望结果                                       |
| `domain`             | str  | 领域 (security/software_engineering/data_science 等 9 个) |
| `skill_type`         | str  | 技能类型 (Algorithmic/Systems/Data_Processing 等)         |
| `primitive_skill`    | str  | 原始技能 (如 "Graph traversal and dependency resolution") |
| `persona`            | str  | 角色 (如 "security analyst", "penetration tester")        |
| `task_complexity`    | str  | 任务复杂度 (short/moderate/complex/intricate)             |
| `command_complexity` | str  | 命令复杂度 (bash-only/bash+code/bash+code+services)       |
| `verifier_kind`      | str  | 验证器类型 (exact_text/metric_threshold 等)               |
| `fixture_kind`       | str  | 夹具类型 (text_only/image/audio/video 等)                 |
| `corpus_kind`        | str  | 语料类型 (legacy/sft_v2/rl_v2)                            |
| `base_image`         | str  | 基础镜像类型 (per_domain/intricate)                       |

## 三、依赖项

### 1. LLM API（必须）

| 项目              | 说明                                                                            |
| ----------------- | ------------------------------------------------------------------------------- |
| **默认模型**      | `gemini/gemini-3.1-pro-preview`                                                 |
| **默认 Provider** | Google Gemini                                                                   |
| **API Key**       | `GEMINI_API_KEY`                                                                |
| **替代方案**      | 国内 API 中转服务（OpenAI 兼容接口）+ `OPENAI_BASE_URL` + `MODEL=openai/模型名` |

**注意**：Stages 1-3 每步都要调用 LLM API，每个任务约 3 次 API 调用。响应速度直接影响总耗时。局域网 API 中转延迟较高（本次实测每次请求约 4-25 秒）。

### 2. Apptainer（必须，Stage 4 需要）

| 项目         | 说明                                          |
| ------------ | --------------------------------------------- |
| **用途**     | 构建任务容器镜像 + 冒烟测试                   |
| **安装方法** | `sudo apt install apptainer`（需添加 PPA 源） |
| **验证**     | `apptainer --version`                         |
| **替代**     | 无替代，项目硬编码调用 `apptainer` 命令       |

**首次运行**需要下载基础容器镜像（约几百 MB），Stage 4 较慢。

## 四、生成的任务如何接入后续流程

### 数据流向

```
generate_tasks  →  generate_solutions  →  analyze  →  upload_to_hf
(本阶段)           (求解 pass@k)          (统计)      (发布到 HF Hub)
```

### 接入 generate_solutions

生成的任务目录结构是 `generate_solutions` 的**直接输入**，不需要任何转换：

```bash
TASKS_DIR=rl_data/output/tasks_smoke \
    bash rl_data/scripts/generate_solutions/run_generate_solutions.sh
```

`generate_solutions` 会：
1. 读取 `task_*/task.json` 获取任务描述和验证器
2. 在每个任务容器中运行 agent 多次（pass@k）
3. 将结果写入 `task_*/solutions/` 目录
4. 生成 `*_summary.json` 汇总 pass@k 结果

### 用于 SFT/RL 训练

- **SFT warm-start**: 生成 ~2.2k 环境 → 运行 `generate_solutions` 各 8 次 → 成功轨迹组成 SFT 语料
- **RL 训练**: legacy + rl_v2 语料拼接 → 通过 `combine_corpora.py` 合并

### 发布到 Harbor 评估

```bash
# 转换为 Harbor 格式
python rl_data/scripts/analyze/convert_to_harbor.py

# 在 Harbor 上评估
harbor run -d "shellagent/ShellAgent-15K-Harbor@latest" --agent vanillux2-agent --model ...
```

**耗时统计**：

| 阶段                   | 耗时                | 说明                             |
| ---------------------- | ------------------- | -------------------------------- |
| Stage 1: 任务模板生成  | ~3.5 min (109s/req) | 2 个任务，API 延迟较高           |
| Stage 2: 初始测试生成  | ~25s (12s/req)      | 较快                             |
| Stage 3: 最终测试生成  | ~48s (24s/req)      | 较慢                             |
| Stage 4: 容器构建+测试 | ~6.6 min            | 首次需下载基础镜像               |
| **总计**               | **~12 min**         | 首次运行；后续 Stages 1-3 可跳过 |

**结果**：`Succeeded: 2, Failed: 0, Overall rate: 100.0%` 

### 4.将任务转换为 Harbor 格式

生成的原始格式任务还可以转为 Harbor 评估所需的格式：

```bash
uv run python rl_data/scripts/analyze/convert_to_harbor.py \
    --src rl_data/output/tasks_smoke \
    --dst rl_data/output/tasks_smoke_harbor
```

**转换结果**：`/data/dhsun/shellagent/rl_data/output` 目录下现有 **两个原始格式任务**（`tasks_smoke/task_*`）和 **两个 Harbor 格式任务**（`tasks_smoke_harbor/task_*`），对应关系一一匹配。

转换后 Harbor 任务的目录结构：


### 已知问题与注意事项

1. **API 延迟高**：商会说 Gemini API 延迟较高，在 Agent 场景中容易超时截断。数据生成阶段（单次调用）影响不大，但后续 `generate_solutions`（多轮对话）可能会有问题
2. **Token 消耗**：生成 2 个任务消耗约 3 次 API 调用（模板+初始测试+最终测试），每次输出约 1500-2000 tokens
3. **Stage 4 并发**：脚本默认 16 个 worker 并发构建，每个约占用 ~1 CPU + ~4GB RAM
4. **断点续跑**：如果 Stage 4 部分失败，删掉 `_stage4_done.jsonl` 重新运行会重试失败的项
