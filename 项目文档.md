# ShellAgent 项目文档

> **项目概述**: ShellAgent 是一个用于训练简单而强大的终端使用 Agent（terminal agent）的项目。它涵盖了**数据生成 → Agent 实现 → 模型训练 → 评估**的完整流程。相关论文：[arXiv:2606.23321](https://arxiv.org/abs/2606.23321)

---

## 一、项目逻辑架构

项目围绕构建终端 Agent 的四个阶段组织：

```
┌─────────────────────────────────────────────────────────────────────┐
│                        ShellAgent 项目工作流                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  ① 数据生成 (Data Generation)                                        │
│  ┌──────────────────────────────────────────────────────────────┐   │
│  │  generate_tasks → generate_solutions → analyze → upload_to_hf │   │
│  │  (创建任务)      (pass@k求解)       (统计分析)   (发布到HF Hub) │   │
│  └──────────────────────────────────────────────────────────────┘   │
│                              ↓                                       │
│  ② Agent 实现 (Agent - Vanillux2Agent)                               │
│  ┌──────────────────────────────────────────────────────────────┐   │
│  │  Harbor Agent + LiteLLM + vanillux prompts                    │   │
│  │  通过 bash 工具与容器交互，求解终端任务                           │   │
│  └──────────────────────────────────────────────────────────────┘   │
│                              ↓                                       │
│  ③ 模型训练 (Training - open-instruct fork)                         │
│  ┌──────────────────────────────────────────────────────────────┐   │
│  │  SFT (监督微调) → DPPO RL (强化学习)                           │   │
│  │  训练 shellagent 系列模型 (2B/4B/9B/27B)                             │   │
│  └──────────────────────────────────────────────────────────────┘   │
│                              ↓                                       │
│  ④ 评估 (Evaluation)                                                │
│  ┌──────────────────────────────────────────────────────────────┐   │
│  │  Harbor eval → Beaker 集群 / 本地评测                          │ │
│  │  在 Terminal-Bench / TB-Lite / SWE-bench 上评测               │   │
│  └──────────────────────────────────────────────────────────────┘   │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 核心创新点

1. **组合式任务生成 (Compositional Generation)**：每个任务是独立从正交轴采样（领域、技能类型、角色、难度、验证器类型等），无需昂贵的多阶段验证
2. **软过滤 (Soft Filtering)**：跳过基于教师模型的质量验证，仅保证任务可执行（容器可构建+测试可通过），质量交给 RL 的软过滤
3. **多模态 Fixture**：在容器中注入图片/音频/视频/二进制文件/包/多服务 compose 等具体工件
4. **分级验证器 (Graded Verifiers)**：从精确文本匹配到度量阈值、对抗语料、模糊等价、多协议验证

## 三、核心模块详解

### 3.1 数据生成管线 (`rl_data/`)

数据生成采用 **4 阶段管线**：

#### 阶段 1: `generate_tasks.py` — 任务创建

```
┌────────────────────────────────────────────────────────────────────┐
│ generate_tasks 内部流程 (每个任务)                                  │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│ ① task_template_gen.py → 从7个正交轴采样 → 生成 task.json         │
│    (组合式采样器: 领域×技能×角色×难度×命令复杂度×验证器×夹具)     │
│                                                                    │
│ ② initial_state_test_gen.py → 生成 test_initial_state.py          │
│    (验证任务开始前的环境状态)                                       │
│                                                                    │
│ ③ completion_test_gen.py → 生成 test_final_state.py (验证器)      │
│    (验证任务完成后的结果, 支持分级验证器)                           │
│                                                                    │
│ ④ apptainer_def_gen.py → 生成 container.def + 构建容器 + 冒烟测试 │
│    (保证任务可执行, 但不验证质量)                                   │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

**7 个组合轴**:

| 轴 | 作用 | 可选值 |
|----|------|--------|
| `domain` (领域) | 覆盖度 | 9 个: security, software_engineering, data_science, data_processing, data_querying, debugging, file_operations, scientific_computing, system_administration |
| `skill_type + primitive skill` | 覆盖度 | 每领域 4-5 个技能类型, 每类型 3-7 个原始技能 |
| `persona` (角色) | 多样性 | 每领域 5-18 个角色 (例如: 安全分析师, 渗透测试员) |
| `fixture_kind` (夹具) | 多样性 | text_only, image, audio, video, stripped_binary, vendored_package, multi_service_compose |
| `task_complexity` (任务复杂度) | 难度 | short → moderate → complex → intricate (≈30-60 命令) |
| `command_complexity` (命令复杂度) | 难度 | bash-only → bash+code → bash+code+services |
| `verifier_kind` (验证器类型) | 难度 | exact_text, metric_threshold, adversarial_corpus, fuzz_equivalence, multi_protocol |

#### 阶段 2: `generate_solutions.py` — 解决方案求解

- 对每个任务运行 N 次 Agent 求解
- 支持两种 solver harness:
  - **bash** (传统): 简短系统提示, 16 步默认
  - **vanillux** (新): mini-swe-agent 风格提示, 64 步默认, 头尾截断
- 收集 pass@k 结果

#### 阶段 3: `analyze.py` — 统计分析

- 分析任务组成/难度分布/平衡性
- 生成摘要表格和 matplotlib 图表
- 支持多种 corpus_kind (legacy/sft_v2/rl_v2)

#### 阶段 4: `upload_to_hf.py` — 发布

- 上传到 HuggingFace Hub
- 生成 parquet 文件便于网页预览
- 可选仅上传已验证 (pass@k>0) 的任务

### 3.2 Agent 实现 (`Vanillux2Agent/`)

```
┌──────────────────────────────────────────────────────┐
│ Vanillux2Agent 工作流                                │
├──────────────────────────────────────────────────────┤
│                                                      │
│ ① setup() → 创建状态目录 /tmp/.vanillux2            │
│    记录初始 cwd 和 env                              │
│                                                      │
│ ② run(instruction, environment, context)            │
│    ├─ 构建 messages: system + user instruction       │
│    ├─ for step in range(max_steps=64):              │
│    │   ├─ _query_with_retry() → LiteLLM API 调用    │
│    │   ├─ _extract_tool_call() → 解析 bash 工具调用  │
│    │   ├─ 格式错误 → _append_format_error() + 重试  │
│    │   ├─ _execute_bash() → Harbor environment.exec │
│    │   ├─ _format_tool_result() → 截断+格式化输出    │
│    │   └─ 检测 SUBMIT_MARKER → 退出                 │
│    └─ 保存 trajectory.json / timing.json / usage.json│
│                                                      │
└──────────────────────────────────────────────────────┘
```

- 基于 **LiteLLM** 直接调用模型 API
- 使用 **Harbor** 的 `BaseEnvironment` 执行命令
- 状态持久化: `cd` 和 `export` 在步骤间保持
- 支持格式错误恢复 (最多 64 次)
- 成本限制 / 上下文窗口超限处理

## 五、语料类型 (Corpus Kinds)

| 类型 | 行为 |
|------|------|
